## تصمیم اجرایی / Execution decision

اولویت P0 نصب واقعی و پایدار است. قابلیت‌های مشابه فقط پس از گذر این مرحله و با پیاده‌سازی مستقل افزوده می‌شوند. اسکن گستردهٔ سروری، شمارندهٔ نمایشی و «IP تمیز» بدون تست شبکهٔ کاربر پذیرفته نیست.

1. Restore trustworthy installation and field evidence before feature expansion.
2. P1: bulk operations, accurate usage/error bounds and quotas with documented Free row costs.
3. P2: manual endpoint lists and opt-in client tests with provenance, time, network class and bounded retention. Registry contribution must exclude subscriber IPs and all credentials.
4. P3/P4: client-specific DNS, fragment/ECH/routing and subscription conversion; validate each output with its real core. Chain egress must disclose fallback behavior and validate destinations.
5. P5: diagnostics, encrypted export/import, upgrade preservation and bilingual guides/screenshots. Never label experimental features stable.

The comparison is incomplete for code-level security, real competitor deployments, precise client-version support and one unresolved repository. These are explicitly pending, not assumed safe or compatible with Free.

### Concrete changes and open diagnosis

- FreePanel's Cloudflare API calls now abort after 30 seconds, including a stalled response body, clear the deadline timer and reject redirects. There is no automatic retry of mutation requests.
- Token verification API outages return a sanitized HTTP 502 / `cloudflare-api-failed` instead of incorrectly claiming `token-invalid`. Invalid credentials and insufficient permissions keep their existing specific responses.
- Regressions reproduced five failures before the fix; the four focused suites passed 40 tests afterward. These are local installation-path results, not proof of Cloudflare field installation.
- The separate personal staging Worker has a temporary GET-only handler trace. Failed public health returned neither its trace header nor its diagnostic JSON, and the UI live stream showed no event. This is inconclusive until the read-only API confirms deployed code/route/version and native Tail events.
- That October 13 diagnostic step later completed under an expiring token, without an owner shell command. [The incident evidence](CLOUDFLARE_STAGING_INCIDENT.md) records code/settings readback, canonical publication and the unresolved failure at that time. This owner diagnostic step is not part of normal user installation.
